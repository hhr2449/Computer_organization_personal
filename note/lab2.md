## 2. 实验过程

### 2.1 整体设计目标

使用 32 位拨码开关和 `push_btn` 按键来控制计算逻辑

也就是使用 32 位拨码开关输入一个 32 位的指令，然后按下按键 `push_btn`，完成指令中给定的操作

操作有以下三种：

1. 从寄存器堆中读出操作数，交给 ALU 运算，并将结果写回指定的目标寄存器
2. 将立即数装进寄存器
3. 从寄存器中读取操作数显示到 led

需要完成四个模块：

1. 按键检测：检测一次按键事件，产生一个时钟周期的执行脉冲 `step`，确保长按不会重复执行指令（之前学数逻实验的时候的 key_pulse 模块，按下一次按键产生一个脉冲，防止长按多次执行）
2. 控制模块：接收拨码开关和按键的输入，与 ALU、寄存器、led 进行交互完成指令要求的任务
3. ALU：进行计算
4. 寄存器：存储数据

### 2.2 按键检测

输入输出信号：

| 信号       | 方向 | 含义                               |
| ---------- | ---- | ---------------------------------- |
| `clk`      | 输入 | 驱动模块工作的系统时钟             |
| `reset`    | 输入 | 高电平有效的复位信号               |
| `push_btn` | 输入 | 原始按键状态，按下为 1             |
| `step`     | 输出 | 检测到一次按下后，拉高一个时钟周期 |

使用寄存器 `btn_prev` 用于保存上一个时钟周期的按键信号状态

当前信号为1，上一个信号为0的时候输出一个脉冲，也就是 step = 1

脉冲只持续一个时钟周期

（由于 push_btn 已经经过了消抖，所以不需要单独做消抖了）



### 2.3 ALU

ALU 要求：

1. 输入两个操作数 a，b（16位）
2. 输入操作类型 op，要求支持10种操作，所以应该为4位
3. 输出结果 y（16位）



输入输出信号：

| 信号 | 方向 | 位宽  | 作用                               |
| ---- | ---- | ----- | ---------------------------------- |
| `a`  | 输入 | 16 位 | 第一个操作数                       |
| `b`  | 输入 | 16 位 | 第二个操作数；移位时表示移动的位数 |
| `op` | 输入 | 4 位  | 选择运算类型                       |
| `y`  | 输出 | 16 位 | 运算结果                           |

支持的操作：

| `op` | 名称 | 运算含义        | SystemVerilog 写法         |
| ---- | ---- | --------------- | -------------------------- |
| 1    | ADD  | 加法            | `a + b`                    |
| 2    | SUB  | 减法            | `a - b`                    |
| 3    | AND  | 按位与          | `a & b`                    |
| 4    | OR   | 按位或          | `a | b`                    |
| 5    | XOR  | 按位异或        | `a ^ b`                    |
| 6    | NOT  | 对 `a` 按位取反 | `~a`                       |
| 7    | SLL  | 逻辑左移        | `a << b`                   |
| 8    | SRL  | 逻辑右移        | `a >> b`                   |
| 9    | SRA  | 算术右移        | `$signed(a) >>> b`         |
| 10   | ROL  | 循环左移        | 将两部分移位结果按位或起来 |

### 2.4 寄存器堆

功能描述：

1. 32个16位寄存器
2. 一个写端口和两个读端口

| 寄存器编号 | 保存的数据   |
| ---------- | ------------ |
| 0          | 永远读出 0   |
| 1          | 一个 16 位数 |
| 2          | 一个 16 位数 |
| …          | …            |
| 31         | 一个 16 位数 |

输入输出信号：

1. `input [4:0] waddr`：写操作的寄存器编号；
2. `input [15:0] wdata`：写操作的数据；
3. `input we`：写操作的使能信号；
4. `input [4:0] raddr_a`：读端口 A 的寄存器编号；
5. `output [15:0] rdata_a`：读端口 A 的寄存器数据；
6. `input [4:0] raddr_b`：读端口 B 的寄存器编号；
7. `output [15:0] rdata_b`：读端口 B 的寄存器数据；

注意写入的数据是需要长期保存的，要使用时序逻辑

读数据可以组合也可以时序

### 2.5 控制逻辑

状态机为：

![image-20261012185703295](https://raw.githubusercontent.com/hhr2449/pictureBed/main/img/image-20261012185703295.png)

有三种指令：

| 指令     | 指令中提供了什么                       | 实际数据从哪里来                     |
| -------- | -------------------------------------- | ------------------------------------ |
| 计算指令 | 源寄存器编号、目标寄存器编号、运算类型 | 操作数来自寄存器堆，写入数据来自 ALU |
| POKE     | 目标寄存器编号、立即数                 | 写入数据直接来自指令中的 `imm`       |
| PEEK     | 要读取的寄存器编号                     | 显示的数据来自寄存器堆               |

1. 对于计算指令，控制逻辑需要从寄存器堆中获取操作数（使用输出端连接寄存器堆的地址接收端，使用输入信号连接寄存器堆的数据输出端），然后将操作数和运算类型传给ALU（使用输出信号连接ALU的输入端）
2. 对于 POKE 指令，写入的 imm 直接从指令中获取，需要将数据写入寄存器堆（使用输出信号连接寄存器堆的写入端口）
3. 对于 PEEK 指令，需要先去寄存器中获取数据，然后输出到 led 模块





控制逻辑作为调度的中心需要连接前面的几个模块：

```
module controller (
    input wire clk,
    input wire reset,

    // 连接寄存器堆模块的信号
    output reg  [4:0]  rf_raddr_a,
    input  wire [15:0] rf_rdata_a,
    output reg  [4:0]  rf_raddr_b,
    input  wire [15:0] rf_rdata_b,
    output reg  [4:0]  rf_waddr,
    output reg  [15:0] rf_wdata,
    output reg  rf_we,

    // 连接 ALU 模块的信号
    output reg  [15:0] alu_a,
    output reg  [15:0] alu_b,
    output reg  [ 3:0] alu_op,
    input  wire [15:0] alu_y,

    // 控制信号
    input  wire        step,    // 用户按键状态脉冲
    input  wire [31:0] dip_sw,  // 32 位拨码开关状态
    output reg  [15:0] leds
);
```

1. 用户输入：

   提供输入端口：

   - 连接按键信号 step
   - 连接拨码开关读取指令

2. ALU：

   提供输入接口：

   - 连接 ALU 的输出信号 y，用于接收结果

   提供输出接口：

   - 连接 ALU 的输入信号 a，b，op

3. 寄存器堆：

   提供输入接口：

   - 连接寄存器堆的数据输出信号，用于接收读端口的数据

   提供输入接口：

   - 连接寄存器堆的编号输入信号，用于输入读写的寄存器编号

### 3.3 整体仿真

```
initial begin
    // 初始化外部输入
    dip_sw = 32'd0;
    touch_btn = 4'd0;
    push_btn = 0;
    reset_btn = 1;

    // 释放外部复位
    #200;
    reset_btn = 0;

    // 等待 PLL 时钟稳定，以及内部复位释放
    wait (dut.locked === 1'b1);
    wait (dut.reset_of_clk10M === 1'b0);

    // 从内部时钟的下降沿开始安排后面的输入
    @(negedge dut.clk_10M);

    // 1. POKE：x1 = 5
    dip_sw = `inst_poke(5'd1, 16'd5);
    #200;
    push_btn = 1;
    #200;
    push_btn = 0;
    #1000;

    // 2. POKE：x2 = 3
    dip_sw = `inst_poke(5'd2, 16'd3);
    #200;
    push_btn = 1;
    #200;
    push_btn = 0;
    #1000;

    // 3. ADD：x3 = x1 + x2 = 8
    dip_sw = `inst_rtype(5'd3, 5'd1, 5'd2, ADD);
    #200;
    push_btn = 1;
    #200;
    push_btn = 0;
    #1000;

    // 4. PEEK：读取 x3，预期 leds = 0008
    dip_sw = `inst_peek(5'd3, 16'd0);
    #200;
    push_btn = 1;
    #200;
    push_btn = 0;
    #1000;

    // 5. SUB：x4 = x1 - x2 = 2
    dip_sw = `inst_rtype(5'd4, 5'd1, 5'd2, SUB);
    #200;
    push_btn = 1;
    #200;
    push_btn = 0;
    #1000;

    // 6. PEEK：读取 x4，预期 leds = 0002
    dip_sw = `inst_peek(5'd4, 16'd0);
    #200;
    push_btn = 1;
    #200;
    push_btn = 0;
    #1000;

    $finish;
end
```

- 第二步：执行 ADD 指令，将 x1 与 x2 相加并写入 x3，再执行 PEEK 读取 x3，检查 LED 是否显示 8，验证加法指令的完整执行流程。
- 第三步：执行 SUB 指令，将 x1 减去 x2 的结果写入 x4，再执行 PEEK 读取 x4，检查 LED 是否显示 2，验证减法指令的完整执行流程。
- 在两次运算后都使用 PEEK 检查结果，同时观察 LED 是否只在执行 PEEK 后更新。
