# 总线实验：SRAM 控制器实验

## SRAM

### SRAM 的结构

可以将 SRAM 想象成一个数组，每个元素都是 32 位无符号整数，即：`uint32_t sram[1048576]`

总共有 4M 的数据，可以对其进行读和写操作

可以把它想象成一张表：有$ 2^{20} $行，每行放 32 个二进制位。**地址负责选择哪一行，数据就是这一行保存的内容。**

读 SRAM 首先给出一个地址，比如地址 `0x123`，就要找到第 `0x123=291` 行的 32 位数据，把数据返回给 CPU。

写 SRAM 则需要按照地址找到对应的数据，然后将新写入的数据填入

### SRAM 的信号

顶层模块中有一下6组结构，其中的输入输出都是相对于 FPGA:

| 信号            | 位宽与方向          | 作用                                 |
| --------------- | ------------------- | ------------------------------------ |
| `base_ram_addr` | 20 位，输出         | 指定访问哪个字                       |
| `base_ram_data` | 32 位，双向 `inout` | 传递读取或写入的数据                 |
| `base_ram_be_n` | 4 位，输出          | 选择这个字中的哪些字节               |
| `base_ram_ce_n` | 1 位，输出          | 片选，决定是否选中 SRAM              |
| `base_ram_oe_n` | 1 位，输出          | 输出使能，控制 SRAM 是否向数据线输出 |
| `base_ram_we_n` | 1 位，输出          | 写使能，控制写入                     |

- base_ram_addr：地址线，用于向 SRAM 传递要访问的地址
- base_ram_data：数据线，用于传入或传出要写或是读的数据

比如要执行：`memory[5] = 0x12345678;`，那么 FPGA 就需要将地址5放到地址线base_ram_addr上，将数据`0x12345678`放到数据线上，这两个内容输出到 SRAM，SRAM 按照要求将对应的数据修改

- be_n：字节使能：一共4位，每一位对应一个字节，0表示选中(**n表示低位有效**)

  ```
  位编号：  [31:24]  [23:16]  [15:8]  [7:0]
  字节：     字节3     字节2    字节1   字节0
  对应使能： be_n[3] be_n[2] be_n[1] be_n[0]
  ```

  一个 addr 对应的是4个字节，但是有时候只想要修改其中的某些字节，这个时候就使用字节使能来控制，比如：

  ```
  原数据：0xA1B2C3D4
  写数据：0x11223344
  be_n：  1101
  ```

  只修改字节1，结果为`A1 B2 33 D4`

- **`ce_n`：片选。** `0` 表示选中芯片，`1` 表示不选中。

- **`oe_n`：输出使能。** 这里的“输出”指 **SRAM 向外输出数据**。读取时需要允许它输出。

- **`we_n`：写使能。** `0` 表示写使能有效，`1` 表示不进行写入。

例如：

| 操作             | `ce_n` | `oe_n` | `we_n` | 谁提供数据         |
| ---------------- | ------ | ------ | ------ | ------------------ |
| 读取             | 0      | 0      | 1      | SRAM               |
| 写入的有效阶段   | 0      | 1      | 0      | FPGA               |
| 空闲时的一种设置 | 1      | 1      | 1      | 双方均可释放数据线 |

读取的时候：选中芯片，允许输出，但是写使能无效

写入的有效阶段：选中芯片，写使能有效，但是输出使能无效，不允许输出

空闲时：三个使能均无效

按照本实验的控制方式，写使能和输出使能应该只有一个有效

### SRAM 的时序

#### 读

<img src="https://raw.githubusercontent.com/hhr2449/pictureBed/main/img/image-20261019214945764.png" alt="image-20261019214945764" style="zoom:50%;" />

SRAM 读取的时候，首先需要根据行号找到相应的行，再把一行的数据输出到 `base_ram_data` 上。

近似认为 SRAM 需要一个控制器时钟周期完成读写（也就是说，在第一个时钟周期开始的时候向地址总线写入要读的地址，此时 SRAM 会开始读取数据并输出到数据线，可以认为在第二个时钟周期开始的时候就可以从数据线上读取到数据了）

> [!tip]
>
> 实际上 SRAM 的读写时间是由 SRAM 芯片本身的特性决定的，但是在实验中采用的时钟频率一般不会太大，可以保证一个时钟周期内完成读写，所以就近似认为读写时间是一个时钟周期

1. 每次读取都需要等待一个周期。等待的时候，地址保持不变
2. 读操作需要保持 `ce_n=0, oe_n=0, we_n=1`
3. 四个字节都读取，于是设置 `be_n=0b0000`
4. 不需要读取的时候，设置 `ce_n=1`

读取一次的时序如下：

| 阶段        | 地址       | `ce_n` | `oe_n` | `we_n` | 控制器做什么           |
| ----------- | ---------- | ------ | ------ | ------ | ---------------------- |
| 读第 1 周期 | 5          | 0      | 0      | 1      | 建立访问，等待数据稳定 |
| 读第 2 周期 | 保持 5     | 0      | 0      | 1      | 采样并保存数据         |
| 结束后      | 可不再保持 | 1      | 1      | 1      | 让 SRAM 恢复空闲       |

#### 写

<img src="https://raw.githubusercontent.com/hhr2449/pictureBed/main/img/image-20261019215910018.png" alt="image-20261019215910018" style="zoom:50%;" />

| 信号或行为      | 第 1 周期：准备 | 第 2 周期：写入 | 第 3 周期：保持 |
| --------------- | --------------- | --------------- | --------------- |
| `addr`          | 5               | 保持 5          | 保持 5          |
| FPGA 输出的数据 | `0xA1B2C3D4`    | 保持不变        | 保持不变        |
| `be_n`          | `0000`          | 保持不变        | 保持不变        |
| `ce_n`          | 0               | 0               | 0               |
| `oe_n`          | 1               | 1               | 1               |
| `we_n`          | **1**           | **0**           | **1**           |

第一周期准备，FPGA 需要给出地址，数据，字节使能。这个时候还没有开始写入，所以oe和we都是1

第二周期正式开始进行写入，此时we设为0

第三周期we设为1，保持

SRAM 具体的写入流程大概分成以下三步：

1. 根据 `addr` 找到对应的行，把一行的数据读取出来
2. 把读取的数据和写入的数据，根据 `be_n` 计算出新的数据，例如原来保存的数据是 `0x12345678`，新写入的数据是 `0x87654321`，如果 `be_n=0b1100`，则新的数据是 `0x12344321`，即只写入两个字节
3. 把新的数据写入到行中

但是我们并不需要关心SRAM如何实现，只需要实现控制器，通过接口控制SRAM即可

## Wishbone 总线协议

### 为什么需要总线协议

CPU 需要访问和操作很多不同的设备，比如内存、网卡、鼠标等

但是各个设备的接口和操作方式都是不同的。总线协议就是给CPU提供统一的访问方式，具体的操作交给设备的控制器进行，这样CPU就不需要去关心设备内部的操控逻辑，只需要以统一的方式来表示自己的需求即可

<img src="https://raw.githubusercontent.com/hhr2449/pictureBed/main/img/image-20261020105750610.png" alt="image-20261020105750610" style="zoom:50%;" />

1. 统一的硬件接口，可以接入不同的硬件外设
2. 统一的软件接口，CPU可以通过同样的方式来操控总线下的所有设备



### Wishbone 总线协议

设备分为:

- Master(主设备)：发起读写请求；在实验中是`sram_tester`，实际系统中是CPU
- Slave(从设备)：接收并处理主设备的请求并且返回结果；即要编写的sram控制器



以下是实验中规定的信号，方向是 master 的视角

| 信号    | 作用                                      |
| ------- | ----------------------------------------- |
| `CLK_I` | 时钟，双方按时钟沿判断传输是否完成        |
| `CYC_O` | 表示当前总线访问周期有效                  |
| `STB_O` | 表示当前有一笔有效请求                    |
| `ADR_O` | 要访问的地址                              |
| `WE_O`  | 读写方向：**1 写，0 读**                  |
| `DAT_O` | Master 提供的写数据                       |
| `SEL_O` | 字节选择，每一位的 **1 表示选中**对应字节 |
| `ACK_I` | Slave 返回的完成应答                      |
| `DAT_I` | Slave 返回的读数据                        |

- cyc表示的是当前周期有效，也就是表示主设备正在占用。而stb是当前的请求有效，表示的是当前主设备要求的一个具体操作

  在当前cyc中可以进行多个具体操作，只有`wb_cyc_i && wb_stb_i`为1从设备才执行当前的请求



例子：**一次读操作按以下过程进行：**

1. Master 给出地址 `ADR_O` 和字节选择 `SEL_O`，设置 `WE_O=0`，并拉高 `CYC_O、STB_O`。
2. Slave 开始处理请求。没有完成时，`ACK_I=0`，Master 继续等待。
3. Slave 完成读取后，提供有效的 `DAT_I`，同时拉高 `ACK_I`。
4. 在时钟上升沿，Master 看到 **`CYC_O && STB_O && ACK_I` 为 1**，就接收读数据，完成这笔传输。

原则：

1. 不能打断正在进行的请求：如果请求有效且上个周期ACK_I=0（请求尚未完成），这个周期必须继续保持`CYC_O && STB_O = 1`，不能中断
2. 等待期间不能修改请求： 地址、读写方向、写数据和字节选择都要保持不变。直到从处理器完成请求
3. 读数据只能在完成请求后进行。没有有效请求，或者 `ACK=0` 时，不能把读数据线上的值当作结果。只有在某个时钟上升沿，master检查发现**`CYC_O && STB_O && ACK_I` 为 1**，才能够读取数据
4. 从处理器只处理有效请求

## SRAM 控制器

![image-20261020113726332](https://raw.githubusercontent.com/hhr2449/pictureBed/main/img/image-20261020113726332.png)

| 状态      | 要完成的事情             | SRAM 侧关键行为                                  |
| --------- | ------------------------ | ------------------------------------------------ |
| `IDLE`    | 等待并接收请求           | SRAM 保持空闲                                    |
| `READ`    | 开始读取，等待数据稳定   | 给出地址，`ce_n=0、oe_n=0、we_n=1`               |
| `READ_2`  | 保存读取结果             | 继续保持读信号；你的代码在离开该状态的时钟沿采样 |
| `WRITE`   | 准备地址、数据和字节使能 | `ce_n=0、oe_n=1、we_n=1`                         |
| `WRITE_2` | 维持写脉冲               | `we_n=0`，其他信号保持                           |
| `WRITE_3` | 结束写脉冲并保持输入     | `we_n=1`，地址和数据继续保持                     |
| `DONE`    | 向 Master 返回完成应答   | SRAM 恢复空闲，`ACK=1`                           |

读写的流程如下：

```
读：IDLE 接收请求
    → READ 设置读信号并等待
    → READ_2 采样保存数据
    → DONE 让 SRAM 空闲，并返回应答

写：IDLE 接收请求
    → WRITE 准备地址和数据，we_n=1
    → WRITE_2 维持写脉冲，we_n=0
    → WRITE_3 结束写脉冲、保持地址和数据，we_n=1
    → DONE 让 SRAM 空闲，并返回应答
```

### 状态机实现技巧

#### 状态切换与控制信号切换

> 问题：当状态切换的时候，如何切换引脚的输入信号

两种思路：

**1. 使用寄存器保存控制信号**

设置一个控制信号的寄存器，在切换状态的时候，就根据下一个状态来更新寄存器的值

然后再使用组合逻辑将寄存器中的值输出给引脚信号

```systemverilog
reg ram_ce_n_reg;

always_ff @ (posedge clock) begin
    if (reset) begin
        state <= STATE_IDLE;
    end else begin
        // ...
        if (STB_I && CYC_I && state == STATE_IDLE) begin
            if (WE_I) begin
                // 在更新状态的同时更新寄存器
                ram_ce_n_reg <= 1'b0;
                state <= STATE_WRITE;
            end
        end
    end
end

// 将寄存器的值赋给信号
always_comb begin
  ram_ce_n = ram_ce_n_reg;
end
```

这种方式的好处是：从寄存器到输出的延迟很小，适合用于访问外设的场景（因为在更新状态的时候就同时更新了寄存器）

**2. 使用组合逻辑计算控制信号**

```systemverilog
always_comb begin
    // default
    ram_ce_n = 1'b1;

    if (state == STATE_WRITE) begin
        ram_ce_n = 1'b0;
    end
end
```

直接使用组合逻辑，根据当前状态计算控制信号

这种方法会引入组合逻辑延迟，因为这个输入信号是状态更新后才进行计算的

#### 控制信号初始化

在 FPGA 刚烧入 Bitstream 的时候，状态机还没有初始化，此时的 SRAM 控制信号（`ce_n`，`we_n` 和 `oe_n`）等可能处于 0，那么 SRAM 就会认为此时的 FPGA 在进行写操作，导致 SRAM 内的数据被覆盖

所以要进行输入信号的初始化

> [!tip]
>
> 注意初始化和复位是不同的
>
> | 情况                      | 哪部分起作用         |
> | ------------------------- | -------------------- |
> | 仿真刚开始／FPGA 配置完成 | 初始化设置初值       |
> | 控制器正常工作            | 状态机不断更新寄存器 |
> | 运行中再次触发复位        | 复位分支恢复安全值   |

**1. 使用寄存器连接控制信号**

```systemverilog
// 初始化：放在模块内部、always_ff 外部
initial begin
    sram_ce_n_reg = 1'b1;
    sram_oe_n_reg = 1'b1;
    sram_we_n_reg = 1'b1;
    sram_be_n_reg = {SRAM_BYTES{1'b1}};
end

// 复位：保留原有状态机逻辑
always_ff @(posedge clk_i) begin
    if (rst_i) begin
        sram_ce_n_reg <= 1'b1;
        sram_oe_n_reg <= 1'b1;
        sram_we_n_reg <= 1'b1;
        sram_be_n_reg <= {SRAM_BYTES{1'b1}};
    end else begin
        // 原有的 case (state_next) 控制逻辑
    end
end

// 将寄存器的值赋给信号
always_comb begin
  ram_ce_n = ram_ce_n_reg;
end
```

使用initial块对寄存器进行初始化即可

**2. 使用组合逻辑计算控制信号**

```systemverilog
always_comb begin
    sram_we_n = 1'b1;  // 每次计算先给默认值

    if (state == STATE_WRITE_2)
        sram_we_n = 1'b0;  // 满足条件时覆盖默认值
end
```

在组合逻辑块中给一个默认值，满足条件的时候才覆盖默认值

## 三态门

实际的数据线连接情况如下：

```
        FPGA 芯片                         SRAM 芯片

       数据引脚 0 ─────── 板上的导线 ─────── 数据引脚 0
       数据引脚 1 ─────── 板上的导线 ─────── 数据引脚 1
           ……                                 ……
      数据引脚 31 ─────── 板上的导线 ─────── 数据引脚 31
```

也就是说 FPGA 和 SRAM 是共用同一条数据线的，发送端控制数据线上的电平，接收端读取数据线上的电平

可以将引脚内部的结构理解为下图：

```
FPGA 内部

输出电路 ──[输出开关]──┐
                     ├── FPGA 引脚 ─── 导线 ─── SRAM 引脚
输入电路 ←───────────┘
```

- 输出开关打开：FPGA 可以把自己想输出的 `0` 或 `1` 驱动到线上。
- 输出开关断开：FPGA 不再控制线上的电平，**但输入电路仍然连着，可以观察线上是什么值**。

传输数据的时候发送端的输出电路打开，将想要输出的电平驱动到线上

而接收端的输出开关应该断开，不控制线上的电平，而输入电路还可以读取线上的值

这种断开的状态就是高阻态z



对应的代码：

```systemverilog
// 输入电路
wire  [31:0] sram_data_i;
// 输出电路
logic [31:0] sram_data_o;
// 输出开关
logic        sram_data_t;
// sram_data就是数据线
// 当sram_data_t为1时，FPGA输出高阻态，也就是断开输出开关，否则将输出电路的数据传给数据线
assign sram_data   = sram_data_t ? 32'bz : sram_data_o;
// 输入电路从数据线获取数据
assign sram_data_i = sram_data;
```

1. 总线地址和sram地址换算

   sram使用的是字地址，也就是sram地址增加1，实际上是跨越了32位即4个字节。而总线地址是字节地址，增加1跨越1个字节

   需要进行两种地址的换算：

   实际上总线地址去掉低两位就是sram地址（相当于单位为2^2=4字节），同时要考虑sram地址只有20位，需要截取
