# 实验环境配置与监控程序

## 1. 配置环境
首先面对的一个问题是：实验用到的指令集是 `riscv`，但是电脑则是`x86-64`，所以需要解决如何在电脑上模拟运行`riscv`指令

- 编译与汇编：将写好的 riscv 汇编文件转换成机器码
- 模拟执行：使用模拟器来执行 riscv 的机器指令

执行：

```shell
sudo apt install -y qemu-system-misc gcc-riscv64-unknown-elf binutils-riscv64-unknown-elf gdb-multiarch
```

| 软件包                         | 用途                                    |
| ------------------------------ | --------------------------------------- |
| `qemu-system-misc`             | 提供包括 RISC-V 在内的多种系统模拟器    |
| `gcc-riscv64-unknown-elf`      | 提供面向 RISC-V 裸机程序的 GCC 编译工具 |
| `binutils-riscv64-unknown-elf` | 提供汇编、链接、反汇编等工具            |
| `gdb-multiarch`                | 提供能调试多种处理器架构程序的 GDB      |

`qemu`负责模拟运行 riscv 的机器指令

中间两个用于提供编译、汇编、链接等功能



## 监控程序的使用

### 基本理解

然后安装课程提供的监控程序：`supervisor-rv`

![image-20260927130515000](https://raw.githubusercontent.com/hhr2449/pictureBed/main/img/image-20260927130515000.png)

kernel 可以理解为一个简化版的操作系统，它运行在指定的计算机上，可以读写内存、查看寄存器、装入指令、运行指定的指令

> [!tip]
>
> kernel 本身运行在指定计算机的内存中，由该计算机的 CPU 进行执行
>
> 这里的计算机可以是 qemu 模拟出来的 riscv 计算机，也可以是大作业用硬件描述语言实现的 CPU 部署在硬件平台上行程的计算机

term 类似一个简化的命令行操作界面，通过串口协议与 kernel 进行交互，还负责调用汇编、反汇编工具

> [!tip]
>
> term 运行在外部计算机上，通过 TCP 连接 kernel 所在计算机上的串口从而实现与 kernel 的交互
>
> 比如之后运行大作业的时候，kernel 会运行在 FPGA 上我实现的 CPU 中，而 term 则运行在自己的电脑上，通过实验平台提供的串口进行交互

### 使用教程

#### 启动 kernel

首先启动 kernel:

```shell
cd ~/cod-lab/supervisor-rv/kernel
make sim
```

这时候会完成以下流程：

```
编译 Kernel，得到 kernel.elf
        ↓
启动 QEMU，创建模拟的 CPU、内存和串口
        ↓
QEMU 把 kernel.elf 中的程序装入模拟内存
        ↓
模拟 CPU 开始执行 Kernel
```

之后想要在 FPGA 上运行的话，则是：

```
1.把 Kernel 的机器码写进开发板内存。
仍然在电脑上构建，课程构建流程可以生成 kernel.bin，然后使用开发板提供的加载工具，将它写到目标计算机的：0x80000000 这个地址开始的内存中。


2.让 CPU 从 Kernel 的入口开始取指。
按照课程约定，设计的 CPU 复位后应从 0x80000000 开始执行。因此，在 Kernel 已经写入内存后，通过复位并释放复位，就可以让 CPU 开始运行它：
```

### 启动 term

然后开启另一个终端运行 term:

```shell
cd ~/cod-lab/supervisor-rv/term
python3 term.py -t 127.0.0.1:6666
```

之后就可以在 term 中与 kernel 进行交互了

### 监控程序指令

| 命令  | 功能                             | 使用顺序示例                                        |
| ----- | -------------------------------- | --------------------------------------------------- |
| **A** | 逐行输入汇编，写入指定内存地址   | `A` → 地址 `80100000` → 逐行输入汇编 → **空行结束** |
| **U** | 读取内存并反汇编，检查装入的指令 | `U` → 地址 `80100000` → 字节数 `24`                 |
| **G** | 从指定地址开始执行程序           | `G` → 入口地址 `80100000`                           |
| **R** | 查看用户程序结束时保存的寄存器值 | 输入 `R`，不需要参数                                |
| **D** | 查看指定内存区域的数据           | `D` → 地址 `80400000` → 字节数 `4`                  |
| **F** | 从文件读取汇编并装入内存         | `F` → 文件路径，如 `program.s` → 地址 `80100000`    |
| **Q** | 退出 Term                        | 输入 `Q`；不会同时关闭 QEMU                         |
| **T** | 查看页表                         | 输入 `T`；实验 1 基础版本未启用分页，暂时不用       |

> [!tip]
>
> 表格中的 `→` 表示按提示进入下一步，**每一步都要回车，不是把整行一次性输入**。
>
> 地址选择：
>
> | 地址范围                 | 用途         | 能否自行选择                   |
> | ------------------------ | ------------ | ------------------------------ |
> | `0x80000000～0x800FFFFF` | Kernel 代码  | 不要用自己的代码覆盖           |
> | `0x80100000～0x803FFFFF` | 用户程序代码 | 可以在这个区域内选择           |
> | `0x80400000～0x807EFFFF` | 用户程序数据 | 一般可以选择，但要遵守题目要求 |

#### 操作实例

在 term 中完成 1+2

1. 使用 A 输入要运行的 riscv 指令

   ```assembly
   >> A
   addr: 0x80100000
   one instruction per line, empty line to end.
   [0x80100000] li t0, 1	# 将1加载到寄存器t0
   [0x80100004] li t1, 2	# 将2加载到寄存器t2
   [0x80100008] add t2, t0, t1		# t0 + t1，结果放在t2
   [0x8010000c] li t3, 0x80400000	# 将存储结果的内存地址放在t3
   [0x80100010] sw t2, 0(t3)	# 将t2的值放入t3中存储的地址
   [0x80100014] jr ra	# 返回
   [0x80100018]
   ```

2. 使用U查看指令

   ```assembly
   >> U
   addr: 0x80100000	# 起始地址
   num: 24	# 要查看的字节数，每条riscv指令是4个字节，6条指令一共24字节
   0x80100000:     00100293        li      t0,1
   0x80100004:     00200313        li      t1,2
   0x80100008:     006283b3        add     t2,t0,t1
   0x8010000c:     80400e37        lui     t3,0x80400
   0x80100010:     007e2023        sw      t2,0(t3)
   0x80100014:     00008067        ret
   ```

3. 使用G执行

   ```assembly
   >> G
   addr: 0x80100000	# 程序入口地址
   
   elapsed time: 0.001s
   ```

   执行结束后会显示时间并返回 term

4. 使用R查看寄存器值

   ```assembly
   >> R
   R1 (ra)    = 0x800002cc
   R2 (sp)    = 0x807f0000
   R3 (gp)    = 0x00000000
   R4 (tp)    = 0x00000000
   R5 (t0)    = 0x00000001
   R6 (t1)    = 0x00000002
   R7 (t2)    = 0x00000003
   ```

5. 使用D查看内存

   ```assembly
   >> D
   addr: 0x80400000
   num: 4
   0x80400000: 0x00000003
   ```
