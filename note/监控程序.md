# 理解监控程序

## 1. kernel

整体流程：

```
初始化数据和栈();
初始化串口();

输出启动信息();

while (1) {
    命令 = 从串口读取一个字节();
    执行对应操作(命令);
}
```

先进行初始化，输出启动信息

然后执行一个死循环，不断从串口中读取命令，执行对应的操作

### 1.1 从入口到初始化

整个 kernel 的入口是`evec.s`，代码如下：

```assembly
INITLOCATE:
    # 将 START 对应的地址放进 s10
    la s10, START
    # 跳转到 s10 进行执行
    jr s10
```

`START`定义在`init.s`中，从这里开始初始化

### 1.2 初始化

首先清空 `bss`:

```assembly
START:
    // 清空 BSS
    // _sbss 和 _ebss 在 ld script 中定义
    # 将 bss 的起始地址和结束地址分别放入 s10 和 s11
    la s10, _sbss
    la s11, _ebss
bss_init:
	# 每次写入一个 word 的 0，直到完全清空
    beq s10, s11, bss_init_done
    sw  zero, 0(s10)
    addi s10, s10, 4
    j   bss_init
bss_init_done:
```

设置用户栈和内核栈：

```assembly
	// 设置内核栈
    la sp, KERNEL_STACK_INIT

    // 设置用户栈
    li t0, USER_STACK_INIT
    // 设置用户态程序的 sp(x2) 和 fp(x8) 寄存器
    // uregs_sp 和 uregs_fp 在 ld script 中定义
    la t1, uregs_sp
    STORE t0, 0(t1)
    la t1, uregs_fp
    STORE t0, 0(t1)
```

用户栈供用户程序使用，内核栈供内核使用

因为现在 kernel 正在运行，所以将内核栈放入 sp 中供内核使用，然后将用户栈栈顶地址放入 t0 中保存

等到要运行用户程序的时候才会将用户栈栈顶地址放入 sp

然后配置串口：

```assembly
// 配置串口，见 serial.h 中的叙述进行配置
    li t0, COM1
    // 打开 FIFO，并且清空 FIFO
    li t1, COM_FCR_CONFIG 
    sb t1, %lo(COM_FCR_OFFSET)(t0)
    // 打开 DLAB
    li t1, COM_LCR_DLAB
    sb t1, %lo(COM_LCR_OFFSET)(t0)
    // 设置 Baudrate
    li t1, COM_DLL_VAL
    sb t1, %lo(COM_DLL_OFFSET)(t0)
    sb x0, %lo(COM_DLM_OFFSET)(t0)
    // 关闭 DLAB，打开 WLEN8
    li t1, COM_LCR_CONFIG
    sb t1, %lo(COM_LCR_OFFSET)(t0)
    sb x0, %lo(COM_MCR_OFFSET)(t0)
    // 打开串口中断
    li t1, COM_IER_RDI
    sb t1, %lo(COM_IER_OFFSET)(t0)
```

完成初始化后输入启动信息，进入 `SHELL` 启动循环：

```assembly
WELCOME:
    // 装入启动信息并打印
    la a0, monitor_version
    jal WRITE_SERIAL_STRING

    // 开始交互
    j SHELL
```

### 1.2 `SHELL`:处理用户指令的主循环

整体流程是：

```
SHELL：等待并读取命令
       ↓
判断命令，跳到相应 .OP_* 分支
       ↓
执行操作
       ↓
.DONE
       ↓
重新进入 SHELL
```



**首先 `SHELL` 读串口，根据收到的命令选择执行位置**

```assembly
SHELL:
    // 读操作符
    jal READ_SERIAL

    // 根据操作符进行不同的操作
    li t0, 'R'
    beq a0, t0, .OP_R
    li t0, 'D'
    beq a0, t0, .OP_D
    li t0, 'A'
    beq a0, t0, .OP_A
    li t0, 'G'
    beq a0, t0, .OP_G
    li t0, 'T'
    beq a0, t0, .OP_T

    // 错误的操作符，输出 XLEN，用于区分 RV32 和 RV64
    li a0, XLEN
    // 把 XLEN 写给 term
    jal WRITE_SERIAL
    j .DONE
```

```assembly
.DONE:
    // 交互循环
    j SHELL
```



`READ_SERIAL`是读串口函数，会等待串口的一个字节到来，将其放置在 a0 中，然后返回

这里读到的就是用户输入的操作符

之后有五个分支，会将 `a0` 和对应的操作符进行比较，如果相同则跳转到对应的处理分支中，处理完成后调用 `DONE` 函数回到 `SHELL` 函数重新开始交互循环

如果读到的操作符不属于任何一个合法操作符，则将 `XLEN` 写给 term，表示错误，然后调用 `DONE` 函数，循环回 `SHELL` 的开头再一次读取一个指令



| 标签    | 执行的操作                             |
| ------- | -------------------------------------- |
| `.OP_R` | 读取内存中保存的用户寄存器值           |
| `.OP_D` | 读取指定地址的一段内存                 |
| `.OP_A` | 把收到的数据写入指定内存               |
| `.OP_G` | 跳到指定地址运行用户程序               |
| `.OP_T` | 查询页表；当前基础版返回“未启用”的标记 |

### 1.3 串口读写

`utils.s`提供基础的串口读写能力

采用`内存映射I/O`:CPU 访问一个地址不一定是再访问 RAM，地址可以指向其他的硬件设备

再当前实验平台中：

| CPU 访问的地址 | 对应的对象                                |
| -------------- | ----------------------------------------- |
| `0x80400000`   | RAM 中的一个位置，可以保存 Fibonacci 结果 |
| `0x10000000`   | 串口的数据寄存器                          |
| `0x10000005`   | 串口的状态寄存器                          |

将两个地址`0x10000000`和`0x10000005`映射到串口的数据寄存器和状态寄存器，这样 CPU 要读写地址`0x10000000`实际上就是在访问串口的数据寄存器，这样就实现了读写串口的功能

`WRITE_SERIAL`:

```assembly
WRITE_SERIAL:
    li t0, 0x10000000

.TESTW:
    lb t1, 5(t0)             # 读取 0x10000005 的状态
    andi t1, t1, 0x20        # 保留 bit 5
    bne t1, zero, .WSERIAL   # bit 5 为 1，可以发送
    j .TESTW                # 否则继续检查

.WSERIAL:
    sb a0, 0(t0)            # 发送 a0 的低八位
    jr ra
```

写个函数实现了向串口写一个字节的功能，会先读取`0x10000005`检查串口的状态，如果显示1就说明可以发送，将 a0 写入`0x10000000`中，否则就继续循环检查

```
bit 0 = 0：当前没有可以读取的数据
bit 0 = 1：可以从数据寄存器取出一个字节
```

读取也是类似的，循环检查状态寄存器，显示1说明可以读取，则将其读入 a0



## 2. term

### 2.1 与 kernel 建立连接

```python
if __name__ == "__main__":
    # para = '127.0.0.1:6666' if len(sys.argv) != 2 else sys.argv[1]

    if sys.version_info[0] != 3:
        print("You MUST use Python3 to run terminal.")
        exit(1)

    parser = argparse.ArgumentParser(description = 'Term for rv32/64 expirence.')
    parser.add_argument('-c', '--continued', action='store_true', help='Term will not wait for welcome if this flag is set')
    parser.add_argument('-t', '--tcp', default=None, help='TCP server address:port for communication')
    parser.add_argument('-s', '--serial', default=None, help='Serial port name (e.g. /dev/ttyACM0, COM3)')
    parser.add_argument('-b', '--baud', default=9600, help='Serial port baudrate (9600 by default)')
    args = parser.parse_args()

    if args.tcp:
        if not InitializeTCP(args.tcp):
            print('Failed to establish TCP connection')
            exit(1)
    elif args.serial:
        if not InitializeSerial(args.serial, args.baud):
            print('Failed to open serial port')
            exit(1)
    else:
        parser.print_help()
        exit(1)
    if not test_programs():
        exit(1)
    Main(not args.continued)
```

进入程序后会先进行参数的解析

| 参数 | 用途                              |
| ---- | --------------------------------- |
| `-t` | 指定 TCP 连接的地址和端口         |
| `-s` | 指定实际串口，例如 `/dev/ttyUSB0` |
| `-b` | 设置实际串口的波特率              |
| `-c` | 跳过等待 Kernel 启动信息的步骤    |

这里有两种连接方式，一种是使用 tcp 连接，对应参数 `-t`，这个一般用于连接本机的 qemu 或是远程的开发平台，另一种是指定实际的硬件串口，对应参数 `-s`，则是对应实际的硬件连接

程序会根据指定的连接方式调用相应的函数建立与 kernel 的连接 `InitializeTCP(args.tcp)`,`InitializeSerial(args.serial, args.baud)`

然后回调用 `test_programs()` 检查依赖的工具

接下来会进入`Main`函数

### 2.2 检测字长

```python
def Main(welcome_message=True):
    global xlen, arch

    if welcome_message:
        output_binary(inp.read(33))
        print('')

    # probe xlen
    outp.write(b'W')
    while True:
        xlen = ord(inp.read(1))
        if xlen == 4:
            print('running in 32bit, xlen = 4')
            arch = 'rv32'
            break
        elif xlen == 8:
            print('running in 64bit, xlen = 8')
            arch = 'rv64'
            break
        elif xlen < 20:
            print('Got unexpected XLEN: {}'.format(xlen))
            sys.exit(1)
    MainLoop()
```

Main 函数中会先接收并且打印欢迎信息

然后向 kernel发送一个 `W`，这回进入 kernel 的无匹配命令的处理分支，kernel 会返回 xlen，此时 term 就可以直到字长是多少了

接着进入主循环与用户交互

### 2.3 进入主循环

```python
def MainLoop():
    while True:
        try:
            cmd = raw_input('>> ').strip().upper()
        except EOFError:
            break
        except KeyboardInterrupt:
            print("")
            print("KeyboardInterrupt")
            continue
        EmptyBuf()
        try:
            if cmd == 'Q':
                break
            elif cmd == 'A':
                addr = raw_input('addr: 0x')
                run_A(int(addr, 16))
            elif cmd == 'F':
                file_name = raw_input('>>file name: ')
                addr = raw_input('>>addr: 0x')
                run_F(int(addr, 16), file_name)
            elif cmd == 'R':
                run_R()
            elif cmd == 'D':
                addr = raw_input('addr: 0x')
                num = raw_input('num: ')
                run_D(int(addr, 16), int(num))
            elif cmd == 'U':
                addr = raw_input('addr: 0x')
                num = raw_input('num: ')
                run_U(int(addr, 16), int(num))
            elif cmd == 'G':
                addr = raw_input('addr: 0x')
                run_G(int(addr, 16))
            elif cmd == 'T':
                run_T()
```

MainLoop 中会进入一个循环：

1. 先输出一个`>>`，然后清空 buffer
2. 等待用户输入指令，进入对应的分支
3. 使用`raw_input`指导用户输入需要的参数
4. 然后调用 run 函数进行实际的执行工作

| 命令 | `MainLoop()` 继续读取的参数 | 后续操作                             |
| ---- | --------------------------- | ------------------------------------ |
| `A`  | 起始地址                    | 调用 `run_A()`，由它继续读取汇编输入 |
| `F`  | 文件名、起始地址            | 调用 `run_F()`                       |
| `R`  | 无                          | 调用 `run_R()`                       |
| `D`  | 地址、字节数                | 调用 `run_D()`                       |
| `U`  | 地址、字节数                | 调用 `run_U()`                       |
| `G`  | 程序入口地址                | 调用 `run_G()`                       |
| `T`  | 无                          | 调用 `run_T()`                       |
| `Q`  | 无                          | 执行 `break`，退出循环               |

这些函数执行完毕返回后进行下一轮循环继续接收下一个用户命令

### 2.4 run_G 与程序计时的实现

```
发送 G 和入口地址
        ↓
收到 Kernel 的开始标志 0x06
        ↓
记录开始时间，持续接收程序输出
        ↓
收到 Kernel 的结束标志 0x07
        ↓
计算时间差，显示用时
```

也就是 kernel 主动向 term 通知程序的开始和结束，term 收到开始标志之后开启计时，等待接收到结束标志后停止计时

1. 发送运行请求

   ```python
   outp.write(b'G')
   outp.write(int_to_byte_string(addr))
   ```

   kernel 收到之后调用`.OP_G`：

   ```python
   li a0, SIG_TIMERSET     # 0x06
   jal WRITE_SERIAL
   ```

   kernel在跳转到用户程序之前会向串口写入一个`0x06`作为开始标志

2. 接收到开始标志后，记录主机时间

   ```python
   ret = inp.read(1)
   
   if ret != b'\x06':
       print("start mark should be 0x06")
   
   time_start = timer()
   ```

   term 一旦接收到开始标志，就会启动 timer 开始计时

3. 运行期间正常接收并输出字符

   ```python
   while True:
       ret = inp.read(1)
   
       if ret == b'\x07':
           break
   
       output_binary(ret)
   ```

   当读取到结束标志的时候才会结束，其余字符都是正常读取和输出

4. 收到结束标志后计算时间差

   用户程序执行 `jr ra` 返回后，Kernel 的 `.USERRET2` 会：

   ```
   保存用户寄存器
       ↓
   恢复内核栈
       ↓
   发送 0x07
       ↓
   返回 SHELL
   ```

   Term 收到 `0x07` 后，结束接收循环，并执行：

   ```python
   elapse = timer() - time_start
   print('elapsed time: %.3fs' % (elapse))
   ```

   得到程序运行用时
